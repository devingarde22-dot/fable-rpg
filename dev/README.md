# Dev-пакет «Лиловая Гарь»

Здесь находятся примеры для вертикального среза GM Copilot и игровой комнаты.

## Файлы

- `ai/copilot-system-prompt.md` — системный промпт, JSON Schema ответа и правила видимости.
- `database/schema.ts` — схема PostgreSQL для Drizzle ORM.
- `server/CampaignRoom.ts` — авторитетная Colyseus-комната для TV, GM и player.
- `server/index.ts` — минимальная регистрация комнаты.
- `client/room-client.ts` — пример подключения клиентов.

## Минимальные зависимости

```bash
pnpm add colyseus @colyseus/schema express drizzle-orm pg zod
pnpm add -D @types/express
pnpm add -D drizzle-kit typescript tsx @types/node
```

## Запуск

```bash
pnpm tsx server/index.ts
```

По умолчанию сервер слушает `localhost:2567`. Для теста в локальной сети слушай на `0.0.0.0` и открывай разные URL-режимы в браузере:

```text
http://<IP-компьютера>:3000/tv
http://<IP-компьютера>:3000/gm
http://<IP-компьютера>:3000/player
```

## Важные ограничения примера

Это каркас, а не production-реализация. Перед использованием нужно добавить:

1. авторизацию и проверку членства пользователя в кампании;
2. сохранение предложений `prepare_spawn` в `command_requests` до подтверждения;
3. транзакцию PostgreSQL при применении подтверждённой команды;
4. серверное чтение шаблона NPC вместо доверия клиентскому payload;
5. очередность/идемпотентность команд через `requestId`;
6. корректные фильтры `gm_only` при отправке состояния;
7. серверные таймеры намерений и восстановления стамины;
8. валидацию входных сообщений через Zod;
9. reconnection и восстановление состояния комнаты;
10. rate limit для AI и GM endpoints.

Клиент никогда не должен самостоятельно менять HP, координаты, карты, намерения или репутацию. Он отправляет команду, а сервер возвращает подтверждённое состояние и события.

## Поток спавна NPC

```text
GM → gm.prepare_spawn
   → сервер проверяет клетки и сохраняет proposal
   → сервер отправляет gm.spawn_proposed только GM
   → GM подтверждает
   → сервер применяет транзакцию
   → scene.spawn_accent (pause + звук + затемнение + жёлтый круг)
   → через 2000 ms scene.spawn_applied
```

## Поток последствий

AI возвращает `suggest_consequences` с 2–5 кандидатами. Они видны только GM. GM выбирает один вариант, после чего backend валидирует разрешённую категорию и записывает событие в `campaign_events`. AI не имеет команды `apply_consequence`.
